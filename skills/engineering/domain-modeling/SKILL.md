# Domain Modeling

1. Read `domains/glossary.yaml`, `domains/context-map.yaml` and the affected domain directories.
2. Challenge overloaded or conflicting terms immediately.
3. Test concepts with normal, invalid and edge scenarios, especially identity, kinship, lineage membership, succession and publication display.
4. Update the canonical glossary and affected domain model as soon as a term is resolved.
5. Keep domain assets free of framework, database and file-layout details.
6. Create a Decision only when the choice is hard to reverse, surprising without context and based on a real trade-off.
7. Update or add domain Eval cases for every new invariant.
