# 产品定义

Genealogy V2 定位为面向宗亲组织、修谱委员会和专业修谱机构的中国式族谱数字化、协同修编、审核治理与谱书出版平台。

## 目标客户

1. 正在组织新修、续修或联修族谱的宗亲组织与修谱委员会；
2. 为多个宗族提供资料采集、编修、校对和出版服务的专业修谱机构；
3. 承担谱牒、地方文献和家族档案整理工作的文化机构。

首期不以个人社交型家谱、泛纪念空间或开放寻亲社区为主要产品方向。

## 核心用户

- 主编、总纂和项目负责人；
- 支、房、户资料负责人；
- 资料采集员、校对员和审核员；
- 专业修谱机构的项目经理与编辑人员；
- 经过授权的族人阅读者。

## 核心价值

1. 大型修谱项目可计划、可分工、可审核、可交付；
2. 正确表达支房、字辈、继嗣、出嗣、兼祧等中国式谱系语义；
3. 将旧谱、口述、碑刻和档案转化为可追溯的结构化事实；
4. 从资料采集、事实审核到谱书出版形成端到端闭环；
5. 数据可迁入、可迁出，并可直接支撑后续续修和版本修订。

## 产品原则

- **专业修谱优先**：先解决真实修谱项目中的组织、资料、审核和交付问题；
- **领域正确优先**：不以简单关系表牺牲中国式复杂谱系语义；
- **证据先于正式事实**：从首个版本起保留基础来源与审核状态，后续再演进完整主张—证据治理；
- **每版纵向闭环**：每个版本都必须具备与其范围匹配的录入、审核、查询、迁出和恢复能力；
- **数据与出版分离**：结构化事实是长期资产，谱书是特定规则和时间点的出版快照；
- **隐私与授权内建**：协作版本即具备基础账号、角色、范围和在世人物保护，商用版再完成细粒度治理；
- **开放可迁移**：各版本按新增资产同步提供可验证迁出，V1.0完成全量标准交付；
- **AI辅助而非替代审核**：AI可以抽取、匹配和提示风险，但不得绕过人工审核写入正式事实。

## 产品边界

当前产品蓝图覆盖完整能力方向，但只对近期版本进行细化。以下方向在形成真实需求前不提前设计实现细节：

- 面向公众的社交网络和内容社区；
- 无授权的跨谱自动人物合并；
- 由 AI 自动确认正式亲属关系；
- 与修谱主流程无关的商城、广告和泛娱乐功能。

## 规划资产

- `releases.yaml`：版本 ID、目标、状态、规划深度和置信度的机器事实源；
- `capability-map.yaml`：能力文件清单和全局规则；
- `capabilities/*.yaml`：按能力组拆分的正式产品能力基线；
- `roadmap.md`：各版本用户闭环、边界、验收、成功指标和风险；
- `changes/`：产品规划和能力调整的评审过程；
- `decisions/`：需要跨版本长期解释的产品取舍。

Capability 的 `primary_domain` 表示产品责任归属，不等同于代码模块归属、编译依赖或直接数据访问权限；具体实现边界必须由领域资产、Architecture Decision 和当前 Change 共同决定。
