# 首批架构决策清单

> 状态：Review

本清单只记录进入实现前必须解决、且会显著影响多个模块的决策。普通实现细节不进入此处。

## ADR-001：前后端技术基线

需要决定：

- 后端 Java 与 Spring Boot 的目标版本；
- 持久化采用 Spring JDBC、MyBatis 或其他单一主路径；
- 前端 React、TypeScript、Vite、Ant Design 的目标版本；
- 构建、测试和代码生成工具；
- 是否在首期引入附件对象存储。

决策原则：

- 单一、稳定、可测试；
- 不继承旧仓双栈迁移包袱；
- 不因未来可能需求提前引入复杂组件。

## ADR-002：谱系当前树存储

候选方案：

- 邻接表 + 递归 CTE；
- 邻接表 + 可重建路径；
- 邻接表 + 闭包表。

评审依据：

- 创建、移动、拆分时的不变量；
- 当前子树授权查询；
- 祖先和后代图谱查询；
- 1 万、10 万和更大节点规模；
- 路径或闭包数据的重建能力；
- PostgreSQL 集成测试和执行计划。

## ADR-003：跨宗族人物身份链接

需要决定：

- 外部人物引用和本地人物链接的数据结构；
- 链接的创建、审核和撤销流程；
- 跨宗族可见字段；
- 两个宗族对同一自然人的不同事实如何并存；
- 是否允许受控共享来源和引文。

基线约束：一个 Person 主对象只归属一个宗族空间。

## ADR-004：历史日期结构

需要决定：

- 精确、年月、年份、约略、区间和未知的统一值对象；
- 原始历法文本保存方式；
- 公历标准化边界；
- 排序和区间查询；
- 农历、年号和地方纪年扩展方式。

基线约束：不得用虚构月日填补缺失精度。

## ADR-005：Assertion 类型化扩展

需要决定：

- 公共 Assertion 头表；
- 人物姓名、亲子、归属、事件等类型化值表；
- 新主张类型的注册和迁移方式；
- 原始 AI/OCR 提取 JSON 与正式类型化主张的边界；
- 首选主张及正式事实采用关系。

基线约束：核心主张不能长期依赖任意 `subject_type + subject_id + value_json`。

## ADR-006：命令信封与处理器版本

需要决定：

- 命令规范化和载荷摘要算法；
- 幂等键作用域；
- 预期资源版本结构；
- Dry Run 结果结构；
- 处理器注册、版本兼容和重放策略；
- 执行失败、重试和补偿状态。

## ADR-007：谱系结构变化授权

需要决定：

- SELF、SUBTREE 范围基于哪个结构版本；
- 移动、拆分和合并时源范围与目标范围校验；
- 受影响成员授权如何收缩或重新确认；
- 审核时和执行时权限变化的处理；
- 权限缓存版本和失效机制。

基线策略：复杂结构命令必须同时覆盖源、目标和全部受影响子树。

## ADR-008：正式事实与主张采用关系

需要决定：

- 正式事实如何引用采用的 Assertion；
- 一个事实是否可以采用多个主张；
- 事实更正后旧采用关系如何保留；
- 反驳证据出现后的再审核流程；
- 正式事实、命令执行和证据之间的查询模型。

## 决策完成标准

每个 ADR 必须包含：

1. 背景和需要解决的问题；
2. 已知业务用例和规模；
3. 候选方案；
4. 选择及原因；
5. 数据、API、权限和测试影响；
6. 不选择其他方案的原因；
7. 负面后果；
8. 重新评审的触发条件。

没有真实用例或验证依据时，应保持未决，不通过个人偏好提前锁定。
