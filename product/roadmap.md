# 产品路线

本路线以“每个版本形成可验证、可迁移、可治理的用户闭环”为原则。版本机器事实以 `releases.yaml` 为准，能力明细以 `capability-map.yaml` 所列 `capabilities/*.yaml` 为准；本文件只描述用户目标、纵向流程、边界、验收、成功指标和风险。

## V0.1 基础谱系纵向验证版

### 用户目标

修谱人员可以创建项目，以基础来源为依据录入人物、家庭单元、普通亲属关系和谱系归属，经简化审核后查询世系、导出结构化成果，并验证最小项目快照可恢复。

### 纵向闭环

项目创建 → 来源登记 → 人物与家庭录入 → 普通关系与谱系归属 → 提交审核 → 正式生效 → 世系查询 → 基础导出 → 快照备份与恢复验证。

### 主要能力

- 修谱项目创建；
- 人物稳定身份、多姓名和基础生平；
- 家庭单元、配偶关系和生物亲子关系；
- 宗派支房户组织、祖先角色和人物谱系归属；
- 基础来源引用与草稿、待审核、正式状态；
- 人物搜索、人物详情、祖先上溯、后裔下查和多代世系图；
- 人物、关系、谱系和基础来源的结构化导出；
- 项目结构化数据、配置和基础来源的最小快照备份与恢复。

### 明确不包含

- 继嗣、出嗣、兼祧和收养等复杂关系；
- 多人分工、细粒度权限和多级审核；
- 主张冲突、证据支持与反驳等完整证据治理；
- 附件全量备份、周期策略、灾难恢复、OCR、谱书排版和商用部署。

### 版本验收

使用完全虚构的三代、两个房支和不少于二十个人物的数据，完成项目创建、来源登记、人物与家庭录入、关系建立、谱系归属、审核生效、三代世系查询、结构化导出，并在清空目标环境后通过项目快照恢复全部范围内数据。

### 成功指标

- 人物稳定身份重复数为 0；
- 关系自环和祖先环漏检数为 0；
- 正式人物、关系和谱系归属的基础来源可追溯率为 100%；
- 导出后人物、家庭关系和谱系节点数量与系统一致；
- 快照恢复后项目、人物、家庭关系、谱系节点、配置和基础来源完整率为 100%；
- 相同数据重复查询结果一致。

### 核心风险

人物、家庭单元、亲属关系、谱系组织、正式事实和恢复边界一旦错误，会传导到全部后续版本；本版本优先验证领域模型和纵向闭环，不追求页面丰富度或商用灾难恢复能力。

## V0.2 资料采集与基础治理版

### 用户目标

修谱委员会可以建立成员账号和基础权限，按支、房、户分配任务；采集人员可以在线或通过 Excel 填报，审核人员可以驳回、补充和确认资料。

### 纵向闭环

账号邀请 → 组织岗位绑定 → 支房任务分配 → 在线或离线采集 → 提交 → 多级审核 → 驳回补充或正式生效 → 进度统计 → 过程数据导出 → 附件与周期备份策略增强。

### 主要能力

- 宗族与机构工作空间、修谱委员会、组织岗位和成员职责；
- 账号认证、成员邀请、账号绑定、基础项目角色与支房数据范围；
- 项目范围、里程碑、任务分配、进度、问题和待办；
- 采集表单、在线填报、Excel 导入导出、草稿、提交和撤回；
- 多级审核、驳回补充、变更与审核操作记录；
- 在世人物基础隐私标记；
- 在 V0.1 快照恢复基础上扩展附件、周期备份策略，以及采集模板、任务和审核记录导出。

### 明确不包含

- 细粒度字段权限、审批权分离和完整隐私运营；
- 复杂中国式承继关系；
- 冲突主张、可信度和完整证据推理；
- 可印刷谱书和自动 OCR。

### 版本验收

由主编建立项目，邀请至少两名支房负责人和一名审核员，分别完成任务领取、在线或 Excel 采集、提交、驳回补充、重新提交和审核通过；系统准确统计进度，并完成附件与周期备份策略验证、恢复验证和过程数据导出。

### 成功指标

- 未授权支房数据访问成功数为 0；
- 任务、提交、驳回和审核状态与进度统计一致率为 100%；
- 审核动作可追溯率为 100%；
- Excel 预检查能够阻断结构错误和越界数据；
- 备份恢复后的任务、数据、附件和审核记录完整率为 100%。

### 核心风险

若账号身份、组织成员、项目角色、谱系范围和审核责任混为一体，后续权限和多租户将难以演进；本版本必须保持这些概念独立。

## V0.3 中国式复杂谱系版

### 用户目标

编修人员可以正确表达中国式复杂亲属、谱籍承继、字辈、世次、历史日期、地点和迁徙信息，并保持查询与迁出语义完整。

### 纵向闭环

复杂案例录入 → 关系维度校验 → 字辈世次计算 → 历史时空关联 → 提交审核 → 关系路径与迁徙查询 → 复杂语义导出。

### 主要能力

- 收养、抚养、继父母、继嗣、出嗣、兼祧、入赘和多婚次；
- 字辈与世次；
- 支房分立、迁移、合并和地域历史；
- 模糊日期、公历、农历和历史纪年；
- 历史地点、生命事件和迁徙事件；
- 亲属关系路径、字辈和世次查询；
- 复杂关系、字辈、历史日期地点和迁徙语义导出。

### 明确不包含

- 多来源冲突分析、可信度和完整证据链；
- OCR 与版面分析；
- 可印刷谱书；
- 跨谱人物匹配。

### 版本验收

使用覆盖继嗣、出嗣、兼祧、收养、再婚和入赘的虚构案例验证：血缘、家庭、法律、抚养和谱籍关系保持独立，世次计算与展示符合各自规则，导出后仍可无损解释。

### 成功指标

- 复杂关系测试案例语义通过率为 100%；
- 不合法祖先环和谱籍承继冲突漏检数为 0；
- 字辈和世次规则可解释率为 100%；
- 复杂语义导出信息丢失数为 0。

### 核心风险

为追求通用性而使用万能关系模型、备注字段或仅在展示层修正，会破坏核心差异化；未支持的关系必须显式标记，不能降级保存。

## V0.4 证据与质量治理版

### 用户目标

每项关键人物和关系事实都可以追溯来源、引文、主张、证据和审核结论；冲突数据可以并存、评审和治理，旧谱扫描件可作为可定位数字资产。

### 纵向闭环

数字资产或来源登记 → 引文定位 → 主张建立 → 证据支持或反驳 → 冲突评审 → 正式事实形成 → 数据质量检测 → 证据链导出。

### 主要能力

- 扫描件与数字资产管理；
- 来源、引文、主张和证据；
- 矛盾主张、可信度和审核形成正式事实；
- 全链路溯源；
- 人物合并拆分、关系争议更正和版本历史；
- 数据冲突检测和质量报告；
- 完整来源、主张、证据、审核和质量信息导出。

### 明确不包含

- 自动 OCR、版面分析和人物关系候选抽取；
- 谱书排版和印刷输出；
- 机构级多租户运营。

### 版本验收

对同一人物或关系构造相互冲突的虚构来源，并关联旧谱扫描页；系统能够并存主张、定位原始资料、展示证据、完成审核、追溯正式结论并导出完整证据链，不通过覆盖历史数据解决冲突。

### 成功指标

- 正式事实全链路可追溯率为 100%；
- 冲突主张被静默覆盖的数量为 0；
- 扫描件、引文区域和主张关联完整率为 100%；
- 人物合并、拆分和关系撤销均可回放和审计；
- 质量报告中的问题能够定位到责任对象和来源。

### 核心风险

如果正式事实直接承载未经审核的录入结果，或把操作日志误当作证据链，后续勘误、数字化和 AI 辅助都将失去可信基础。

## V0.5 谱书编修与出版版

### 用户目标

编修人员可以从审核后的结构化事实编排谱书，以基础隐私规则生成可评审 PDF、不可变出版快照和可复现交付包。

### 纵向闭环

选择正式事实 → 组织目录与文化内容 → 配置显示和脱敏规则 → 生成快照 → PDF 预览校对 → 冻结版本 → 快照、规则和生成物交付。

### 主要能力

- 谱书项目、目录和编辑内容；
- 祠堂、墓葬、碑刻和文化资料；
- 世系图和世系录生成；
- 编排、姓名显示和内容选择规则；
- 基础授权阅读、隐私脱敏与内容排除；
- 不可变出版快照；
- PDF 预览与印刷输出；
- 出版快照、规则和生成物交付包。

### 明确不包含

- 商用级细粒度权限、灾难恢复和私有化部署；
- 自动 OCR 入库；
- 多项目机构运营和计费。

### 版本验收

基于虚构项目生成一部包含目录、序跋、世系图、世系录和文化资料的可重复 PDF；验证在世人物按基础规则脱敏，相同快照和规则产生一致结果，交付包能够复现出版版本。

### 成功指标

- 相同快照重复生成的内容差异为 0；
- 未授权敏感信息进入出版物的数量为 0；
- 每个出版内容项能够追溯正式事实或编辑来源；
- PDF 关键版式阻断问题为 0；
- 交付包复现成功率为 100%。

### 核心风险

若出版直接读取持续变化的数据，或显示规则与快照未冻结，将无法重现已交付谱书；出版模型不得反向成为领域事实源。

## V1.0 商用加固与真实项目交付版

### 用户目标

客户可以在 V0.1—V0.5 已验证的纵向能力上，安全、稳定地完成一部获得授权的真实族谱项目，并通过隐私、安全、恢复、性能和交付验收。

### 商用加固能力

- 商用级权限策略、审批权分离和细粒度数据范围；
- 隐私授权、同意、保留、更正、撤回和删除请求；
- 商用安全审计与日志治理；
- 灾难恢复与恢复演练；
- 全量数据迁出、标准交付和受控旧系统迁移；
- 来源权利与使用许可；
- 私有化部署、开放 API、性能容量和运维监控；
- 谱书勘误、再版和完整项目归档。

### 版本验收

选择一部获得授权的真实族谱项目全程使用系统，完成采集、审核、复杂关系、证据治理、谱书和数据交付；通过权限越权、隐私、来源权利、备份恢复、灾难恢复、性能、数据迁出和私有化部署验收。

### 成功指标

- 高风险权限越权测试通过率为 100%；
- 真实项目关键正式事实可追溯率为 100%；
- 全量迁出完整性校验通过；
- 备份和灾难恢复演练达到约定目标；
- 核心查询和出版作业满足容量基线；
- 客户完成数据与谱书双交付验收。

### 核心风险

将商用能力集中为首次建设会导致大爆炸版本；因此 V1.0 只允许做商用级加固和真实项目验证，基础来源、授权、备份、审计和迁出能力必须已在 V0.x 形成。

## V1.1 旧谱智能数字化候选版

### 用户目标

专业人员可以将旧谱扫描件转化为可校对、可追溯的结构化候选数据。

### 候选能力

- OCR 文字识别和版面定位；
- 谱式与版面区域分析；
- 人物、姓名和关系候选抽取；
- 原图、文本、结构候选和正式数据对照校对；
- 批量匹配、导入预览、回滚和质量报告。

### 约束

所有识别和抽取结果只能形成候选主张，必须经过人工校对和证据审核后才能成为正式事实。

## V1.2 专业机构运营候选版

### 用户目标

专业修谱机构可以同时管理多个客户和项目，复用模板并与外部服务商进行受控协作。

### 候选能力

- 专业机构多项目运营；
- 项目、表单、流程和出版模板；
- 多租户和客户隔离；
- 外部专家与服务商受控协作；
- 商业版本、项目套餐和容量计费；
- 机构级进度、质量、资源和交付看板。

## V2.0 平台与生态候选版

### 用户目标

在明确授权、隐私、证据和审计边界下，探索跨谱协作、专家服务、移动采集和受控 AI 辅助。

### 候选能力

- 跨谱人物候选匹配和人工确认；
- 跨机构授权协作；
- 专家审核和服务商生态；
- 公共谱牒资料索引；
- 移动端受控采集；
- 族人受控参与；
- AI 资料抽取、匹配、冲突提示和编修建议。

### 约束

候选能力不构成交付承诺。任何跨谱匹配和 AI 能力不得自动合并人物、确认亲属关系或绕过来源证据、授权和人工审核。

## 规划深度规则

- 全产品：维护稳定能力 ID、价值、类型、主责任领域、协作领域、依赖、目标版本、版本内承诺级别、状态和规划置信度；
- V0.1—V0.3：维护详细用户流程、边界、验收、成功指标和风险；
- V0.4—V0.5：维护有边界的用户闭环和验收，不提前固化实现；
- 当前正在开发的版本：通过独立 Change 维护详细 Spec、设计、任务和测试；
- V1.0：只维护商用结果和强制约束；
- V1.1 以后：按候选方向管理，不提前设计页面、接口、数据库和具体技术实现。
