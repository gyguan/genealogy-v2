# 产品定义

> 状态：Review

## 1. 产品定位

Genealogy V2 是面向宗亲会、修谱委员会、谱牒研究者和普通族人的中国式族谱协作平台。

它的核心价值不是保存一批人物资料，也不是单纯绘制家谱树，而是：

> 对谱系组织、人物身份、家庭关系、历史事件和文化资料形成可解释、可引用、可审核、可追溯的正式族谱事实。

## 2. 目标用户

| 用户 | 核心任务 | 系统必须解决的问题 |
|---|---|---|
| 主编 / 修谱委员会 | 制定修谱范围、审核争议、发布正式事实 | 多人协作下如何保持事实一致和责任清晰 |
| 支系负责人 | 维护授权谱系范围内的人物和关系 | 如何表达支、房、派的层次及历史变化 |
| 采集员 | 录入人物、关系、事件和来源 | 如何先记录线索，再提交可审核主张 |
| 谱牒研究者 | 对照原谱、地方志和口述材料 | 如何从正式结论追溯到引文和证据 |
| 普通族人 | 查找本人、亲属、世系和文化资料 | 如何在保护在世人物隐私的前提下查谱 |
| 系统管理员 | 管理成员、权限、审计和数据任务 | 如何保证授权范围、导出和敏感操作可审计 |

## 3. 核心业务闭环

```text
建立宗族空间
  → 建立谱系组织
  → 录入人物身份与姓名
  → 建立谱系归属和家庭关系
  → 记录历史事件、日期与地点
  → 登记来源和引文
  → 提出事实主张并关联证据
  → 提交修谱命令
  → 审核、执行并形成正式事实
  → 通过图谱、档案和谱书查看或导出
```

## 4. 核心能力范围

### 4.1 谱系组织

- 表达宗族内的派、支、房等组织单元；
- 支持组织单元的建立、拆分、合并、迁入、迁出和更名；
- 同时保存当前组织结构和历史演变事实；
- 组织结构参与权限范围和图谱查询。

### 4.2 人物身份与谱系归属

- 一个人物拥有稳定身份，不以姓名作为唯一标识；
- 支持谱名、名、字、号、曾用名等多种姓名；
- 支持一个人物在不同语义下归属多个谱系组织；
- 字辈、世次和排行依附具体谱系归属，不作为人物全局唯一属性；
- 跨宗族人物通过受控外部引用或身份链接表达，不共享数据库主对象。

### 4.3 家庭、伴侣与亲子关系

- 家庭结合、伴侣关系和亲子关系分别建模；
- 支持生物、收养、继养、监护、继嗣、出嗣和兼祧等中国式谱系语义；
- 同一人物可处于多个家庭单元或历史关系中；
- 家庭事实不直接等同于谱系组织归属。

### 4.4 历史日期、地点与事件

- 日期支持精确、年月、年份、约略、区间和未知；
- 地点支持历史名称、现代映射和层级关系；
- 出生、死亡、婚姻、迁徙、入继、出嗣、安葬等统一作为历史事件表达；
- 历史发生时间与系统记录时间分别保存。

### 4.5 来源、引文、主张与证据

- 来源描述材料本身，例如族谱、地方志、碑刻、照片或口述记录；
- 引文描述材料中的具体位置和原文片段；
- 主张描述“该材料支持什么事实判断”；
- 证据描述主张与来源之间的支持、反驳或不确定关系；
- 证据记录不能绕过业务审核直接修改正式事实。

### 4.6 修谱命令、审核与生效

- 正式事实的新增、修改、撤销和结构变化通过类型化业务命令完成；
- 提交内容在审核期间保持不可变；
- 提交人不能审核自己的变更；
- 审核通过后由对应领域处理器验证版本、权限和不变量并执行；
- 已执行命令通过反向命令或补偿命令修正，不物理回滚审计历史。

### 4.7 权限、隐私与审计

- 权限由角色、宗族、谱系范围、对象关系、事实状态和隐私等级共同决定；
- 在世人物的联系方式、地址、照片、附件和敏感事件默认不公开；
- 查询、下载、导出、审核、授权和正式事实变更需要相应审计；
- 前端隐藏按钮不能替代后端授权。

### 4.8 查询、图谱与谱书

系统至少提供三类语义明确的图谱：

1. **世系图**：以正式亲子和承继事实为主；
2. **家庭图**：展示家庭单元、伴侣和子女；
3. **谱系组织图**：展示派、支、房的当前结构和历史变化。

图谱只消费正式读模型，不承担写入。

## 5. 首期非目标

以下内容不作为首期基线：

- 与旧仓库的数据和 API 实时兼容；
- 自动判断争议谱系事实；
- 通过 AI 自动把线索直接写入正式库；
- 面向互联网的开放社交网络；
- 微服务拆分、多地域部署和复杂消息平台；
- 未经真实用例验证的通用知识图谱平台；
- 一次性覆盖所有地方谱牒习俗。

AI 可以辅助识别、整理、比对和生成候选主张，但不能代替权限校验、业务审核和正式生效。

## 6. 产品原则

1. **事实优先于页面。** 页面服务于事实表达，不反向决定领域模型。
2. **争议可以保留。** 系统允许存在多个主张和证据，不强迫提前覆盖。
3. **正式事实必须可解释。** 能够回答由谁、何时、基于什么证据、通过什么命令形成。
4. **历史不可被当前结构覆盖。** 当前归属变化不抹去曾经的组织和关系事实。
5. **隐私默认保护。** 缺少明确授权时选择更小披露范围。
6. **文化差异通过受控扩展表达。** 不使用无限枚举或万能 JSON 逃避建模。

## 7. 成功标准

首个可发布版本至少能够：

- 建立一个包含派、支、房层级的宗族空间；
- 录入同一人物的多个姓名和多个谱系归属；
- 表达一个普通家庭和一个继嗣/出嗣场景；
- 使用历史日期和地点记录关键事件；
- 从正式人物或关系追溯到引文和来源；
- 完成提交、审核、执行、审计的闭环；
- 在权限过滤后展示三类图谱；
- 导出经过权限裁剪的结构化数据或谱书结果；
- 对关键不变量提供数据库集成测试和端到端验收。
