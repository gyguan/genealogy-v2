# 前端信息架构与设计系统

> 状态：Review

## 1. 设计目标

前端必须帮助用户完成“建谱、修谱、审谱、查谱”，而不是把数据库表和技术字段搬到页面。

设计优先级：

1. 业务含义清楚；
2. 页面结构一致；
3. 正式事实、草稿、争议和权限状态可辨识；
4. 高密度管理任务操作高效；
5. 图谱和文化内容具有适度的谱牒特征；
6. 在常见桌面宽度和移动端保持可用；
7. 前端不制造后端未返回的业务事实。

## 2. 视觉方向

延续现有原型中已经证明有效的管理端风格，但重新统一为正式设计系统：

- 灰白色工作区；
- 白色侧边栏和内容卡片；
- 蓝色作为操作主色；
- 暖棕色只用于堂号、谱牒、迁徙和文化内容的低饱和强调；
- 清晰边框、轻阴影、紧凑数据密度；
- 不使用大面积渐变、装饰性背景和过度拟物效果。

建议基础参数：

| 项目 | 规范 |
|---|---|
| 左侧导航宽度 | 248px |
| 顶栏高度 | 56px |
| 内容区外边距 | 桌面 24px，窄屏 12px |
| 常用间距 | 8 / 12 / 16 / 24 / 32px |
| 卡片圆角 | 12px |
| 表单控件圆角 | 8px |
| 默认字号 | 14px |
| 页面标题 | 22–24px |
| 主色 | `#1677ff` 或主题等价值 |
| 文化强调色 | 低饱和暖棕，不替代全局主色 |

实现阶段优先使用 React、TypeScript 和 Ant Design 的主题令牌与标准组件；只有图谱画布和谱牒文化展示允许自定义绘制。

## 3. 全局信息架构

一级导航按用户任务分组：

### 总览

- 族谱首页；
- 我的待办；
- 最近变更。

### 建谱

- 建谱向导；
- 谱系组织；
- 人物档案；
- 家庭关系；
- 世系图谱。

### 资料

- 来源资料库；
- 主张与证据；
- 历史事件；
- 宗族文化。

### 协作

- 修谱工作台；
- 审核中心；
- 导入任务；
- 导出任务。

### 管理

- 成员与权限；
- 隐私策略；
- 审计追踪。

菜单是否显示由后端返回的能力和范围决定，但菜单隐藏不构成授权。

## 4. 应用外壳

```text
Layout
├── Sider
│   ├── 产品标识
│   ├── 分组菜单
│   └── 可选的当前宗族切换入口
├── Header
│   ├── 当前模块
│   ├── 当前宗族 / 谱系范围
│   ├── 全局搜索或必要快捷入口
│   └── 用户菜单
└── Content
    └── StandardPage
```

要求：

- 侧边栏在桌面端固定或吸顶；
- 顶栏高度固定为 56px；
- 内容区不设置固定最小宽度导致横向溢出；
- 页面切换保留 URL 状态；
- 编辑页面离开前必须处理未保存状态；
- 提交中的页面禁止重复提交或无提示离开。

## 5. 标准页面模式

所有普通业务页面使用统一层次：

```text
页面标题 + 说明 + 当前范围 + 一个页面级主操作
  → 可选状态提示 / 前置条件
  → 查询或筛选区
  → 结果、详情或工作区
  → 分页 / 后续动作
```

### 5.1 页面头

必须包含：

- 业务标题；
- 一句话说明；
- 当前宗族、谱系或隐私范围；
- 最多一个页面级主按钮；
- 返回操作只在详情和编辑层级出现。

禁止：

- 展示内部模块名、表名或接口路径；
- 在标题区堆放多个同权主按钮；
- 页面标题与卡片标题重复表达同一内容。

### 5.2 查询区

- 使用 Card + Form；
- 常用条件默认展示，高级条件折叠；
- 查询和重置位置固定；
- 字段间距和提示空间保持一致；
- 查询条件进入 URL，便于返回、分享和刷新；
- 不要求用户输入数据库 ID。

### 5.3 结果区

- 列表优先使用 Table；
- 人物等移动端高频场景可提供 Card List；
- 标题显示结果数量；
- 页面级操作与结果级操作分离；
- 稳定排序和分页由后端负责；
- 关键列不可在中等宽度下无提示消失；
- 次要列使用响应式规则、横向滚动或“更多”收纳。

### 5.4 页面状态

每个页面必须完整处理：

- 初始加载；
- 局部刷新；
- 空数据；
- 前置条件缺失；
- 无权限；
- 网络或业务错误；
- 提交中；
- 提交成功；
- 数据已被他人修改；
- 查询结果被权限裁剪或达到上限。

## 6. 关键页面模式

### 6.1 族谱首页

结构建议：

1. 4–6 个核心 KPI；
2. 谱系组织和代次分布；
3. 待办、风险与争议；
4. 最近正式变更；
5. 快捷入口。

指标必须来自后端聚合接口。点击指标通过 Drawer 或目标列表下钻，不用固定数字填充页面。

### 6.2 建谱向导

建谱顺序：

```text
宗族空间
  → 谱系组织
  → 字辈方案
  → 人物身份
  → 谱系归属
  → 家庭与亲子
  → 来源和证据
  → 提交审核
  → 查看正式结果
```

每一步展示：

- 前置条件；
- 当前任务；
- 已完成结果；
- 未完成原因；
- 下一步入口。

步骤状态来自业务 API，不通过 DOM 探测或前端猜测。

### 6.3 人物档案

列表重点展示：

- 首选姓名；
- 其他姓名摘要；
- 性别；
- 主要谱系归属；
- 字辈和世次；
- 在世/已故的可见状态；
- 正式、草稿或争议状态；
- 当前用户可执行动作。

详情页按以下分组：

- 身份与姓名；
- 谱系归属；
- 家庭与亲子；
- 历史事件；
- 来源、引文与证据；
- 变更和审计。

不以一个超长表单承载所有信息。

### 6.4 谱系组织

推荐“左树右详情”或“树 + Drawer”模式：

- 当前树用于浏览和选择；
- 历史沿革使用 Timeline 或事件列表；
- 拆分、合并、迁移和更名使用专用命令表单；
- 结构变化必须先显示影响范围和权限变化；
- 禁止直接拖拽后立即修改正式结构。

### 6.5 家庭关系

- 家庭结合使用独立卡片；
- 伴侣与子女角色明确标识；
- 生物、收养、继养、监护和谱系承继采用不同文案和图例；
- 复杂继嗣命令先展示变更预览，再提交审核；
- 不使用一张“关系类型”下拉框承载全部业务。

### 6.6 来源与证据

来源详情应明确区分：

- 材料元数据；
- 附件；
- 引文；
- 主张；
- 支持或反驳证据；
- 已采用的正式事实；
- 争议和审核记录。

用户不能因上传附件而误以为事实已经正式生效。

### 6.7 审核中心

使用 Tabs 区分：

- 待我审核；
- 我提交的；
- 已处理；
- 执行失败或需补偿。

审核详情必须展示：

- 业务化变更摘要；
- 影响对象和范围；
- 变更前后差异；
- 来源和证据；
- 权限与冲突检查；
- 提交人和处理器版本；
- 通过、驳回或请求补充。

审核页面不能只展示原始 JSON。

### 6.8 三类图谱

图谱通用结构：

```text
标准筛选工具栏
  → 图谱画布
  → 节点详情 Drawer
  → 图例、上限和截断提示
```

世系图、家庭图和组织图必须使用不同图例和语义，不把所有边统一绘制为模糊连线。

## 7. 表单与交互

- 使用标准 Form、Input、Select、DatePicker、Radio、Checkbox、Upload；
- 历史日期使用专用组件表达精度、约略和区间；
- 大表单按业务主题拆分 Card；
- 一个操作区最多一个 primary 按钮；
- 删除、驳回、撤销和补偿使用危险样式和二次确认；
- 表格行操作优先使用链接按钮或 Dropdown；
- 成功使用轻量反馈，失败保留可操作错误信息；
- 冲突错误必须提供刷新、比较或重新提交入口。

## 8. 业务文案

页面使用用户语言，不展示：

- 数据库主键；
- 内部枚举值；
- 表名和字段名；
- 存储路径、文件摘要和处理器类名；
- 接口路径和异常堆栈；
- 原始命令 JSON。

示例：

| 技术字段 | 页面文案 |
|---|---|
| `LINEAGE_SUBTREE` | 当前支系及下级范围 |
| `PENDING_REVIEW` | 待审核 |
| `ADOPTIVE_FATHER` | 养父 |
| `effective_from` | 历史有效时间 |
| `recorded_at` | 系统记录时间 |

## 9. 数据真实性

页面业务内容只能来自：

- 后端接口；
- 用户输入；
- 明确标记的原型或测试数据；
- 经过批准的静态字典。

禁止为了视觉丰富而补造人物传记、堂号、迁徙路线、来源材料、审核结论或统计数据。

后端未返回时展示：

- 暂无记录；
- 待补充；
- 未知；
- 无权查看；
- 结果已裁剪。

## 10. 响应式与可访问性

至少验证：

- 1920px；
- 1440px；
- 1366px；
- 1280px；
- 768px 以下移动布局。

要求：

- 关键操作可通过键盘完成；
- 图标按钮具有可读标签；
- 状态不只依赖颜色；
- Drawer、Modal 和图谱节点管理焦点；
- 表格横向滚动区域可聚焦并有说明；
- 图谱提供列表或文本替代视图；
- 窄屏不静默隐藏关键业务字段。

## 11. 样式治理

- 主题集中配置，不在业务组件散落主题色；
- 自定义样式使用 Feature 前缀；
- 不新增全局 `button`、`input`、`.card` 等污染选择器；
- 不覆盖 Ant Design 内部实现类来修复局部问题；
- 文化风格只在明确内容区域使用；
- 图谱节点使用设计令牌，不另起字体、颜色和阴影体系。

## 12. 页面验收清单

- [ ] 标题、说明、范围和主操作是否清楚？
- [ ] 是否只有一个页面级主操作？
- [ ] 查询、结果和详情层次是否统一？
- [ ] 是否完整处理加载、空、错误、无权限和冲突？
- [ ] 页面是否没有技术字段和虚构业务内容？
- [ ] 权限与隐私结果是否以后端返回为准？
- [ ] 正式、草稿、争议和已驳回状态是否可辨识？
- [ ] 1280–1920px 下关键列是否保持可用？
- [ ] 键盘、焦点、标签和非颜色状态表达是否完整？
- [ ] 图谱是否明确表达其关系语义和查询上限？
