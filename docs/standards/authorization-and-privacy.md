# 权限与隐私规范

> 状态：Review

## 1. 目标

权限系统必须回答四个问题：

1. 当前用户是谁？
2. 用户在当前宗族空间中承担什么角色？
3. 用户可以作用于哪些谱系、人物或资源范围？
4. 对当前对象和字段，允许查看、提出变更、审核、执行还是导出？

授权不是菜单控制，也不是一个 `is_admin` 字段。

## 2. 授权模型

授权决策由以下维度共同组成：

```text
身份
  + 宗族成员关系
  + 角色能力
  + 资源范围
  + 对象当前状态
  + 对象与用户的关系
  + 字段隐私等级
  + 操作类型
  + 风险策略
```

统一表达：

```text
Decision = Policy(
  actor,
  clanSpace,
  action,
  resource,
  scope,
  objectState,
  privacyContext
)
```

默认拒绝；只有明确规则允许时才授权。

## 3. 首批角色

角色描述责任集合，不直接写死为页面菜单。

| 角色 | 典型责任 |
|---|---|
| Clan Administrator | 管理宗族空间、成员、全局策略和高风险任务 |
| Chief Editor | 管理修谱范围、审核正式事实和发布结果 |
| Lineage Steward | 维护授权谱系范围内的人物、归属和关系 |
| Contributor | 录入草稿、来源、引文和候选主张 |
| Reviewer | 审核被分配且不存在职责冲突的变更 |
| Researcher | 查看授权来源、引文、争议和历史材料 |
| Member | 查看允许披露的本人、亲属和族谱信息 |
| Auditor | 只读查看审计、授权和高风险操作记录 |

角色能力使用稳定权限代码表达，例如：

```text
PERSON_VIEW
PERSON_CHANGE_PROPOSE
KINSHIP_CHANGE_PROPOSE
CHANGE_REVIEW
CHANGE_EXECUTE
SOURCE_SENSITIVE_VIEW
EXPORT_CREATE
ACCESS_GRANT_MANAGE
AUDIT_VIEW
```

## 4. 资源范围

### 4.1 CLAN

作用于整个宗族空间。

### 4.2 LINEAGE_SELF

只作用于指定谱系组织单元本身。

### 4.3 LINEAGE_SUBTREE

作用于指定单元及其当前下级范围。

必须明确：

- 范围基于当前组织结构；
- 结构变化后缓存立即失效；
- 高风险结构命令不能利用变更后的结构扩大自身权限。

### 4.4 PERSON_SET

作用于明确的人物集合，适用于家庭协作、本人资料维护或特殊授权。

### 4.5 RESOURCE

作用于特定来源、附件、审核任务、导入批次或导出任务。

## 5. 结构变化时的授权

谱系移动、拆分、合并等操作会改变授权范围，因此必须同时校验：

1. 提交前，用户是否有权对受影响源范围发起命令；
2. 目标位置是否在用户可管理范围内；
3. 执行时，权限是否仍然有效；
4. 变更后是否产生越权的成员授权；
5. 是否需要自动收缩、暂停或重新确认相关授权。

首期采用保守策略：

> 结构变更命令要求提交人和执行策略同时覆盖源范围、目标范围及全部受影响子树。

不能仅按变更后的结构判断权限。

## 6. 操作阶段权限

正式变更至少区分：

- `SUBMIT`：可以提出变更；
- `REVIEW`：可以审核该类命令和该资源范围；
- `APPLY`：可以执行并写入正式事实；
- `COMPENSATE`：可以发起或批准补偿命令。

即使同一角色同时拥有这些能力，也必须执行职责隔离：

- 提交人不得审核自己的命令；
- 审核人不得通过改变角色或范围规避隔离；
- 高风险命令可以要求不同的审核人和执行人；
- 系统自动执行仍需记录策略身份和处理器版本。

## 7. 隐私分类

### 7.1 对象隐私等级

建议首批等级：

| 等级 | 说明 |
|---|---|
| PUBLIC | 可在公开谱书或公开页面披露 |
| CLAN_ONLY | 仅当前宗族成员可见 |
| LINEAGE_ONLY | 仅授权谱系范围可见 |
| RELATIVES_ONLY | 仅本人和满足亲属策略的成员可见 |
| PRIVATE | 仅本人、授权编辑和管理员可见 |
| SEALED | 仅特殊授权和审计流程可访问 |

### 7.2 字段分类

同一人物对象内部字段可以具有不同等级：

- 公共谱牒字段：姓名、谱名、世次等；
- 一般个人字段：出生年份、职业、简介；
- 敏感字段：联系方式、详细地址、照片原件；
- 高敏字段：证件、医疗、收养争议、未公开亲子结论；
- 封存材料：遗嘱、司法材料或明确要求封存的附件。

不能只依赖人物对象整体隐私等级。

## 8. 在世人物保护

在世状态为在世、可能在世或未知且未达到明确历史阈值时，采用更严格策略。

默认规则：

- 不公开联系方式和详细地址；
- 不公开证件和高分辨率敏感附件；
- 不在公开导出中包含未获授权的照片；
- 不公开争议亲子、收养、婚姻和健康信息；
- 公开页面只展示经过批准的最小谱牒字段；
- 无法确认是否在世时按在世处理。

死亡事实本身也可能具有证据和审核状态，前端不得通过年龄自行推断。

## 9. 亲属关系授权

`RELATIVES_ONLY` 不能简单解释为“图上能连通”。

亲属访问策略必须明确：

- 使用哪类正式关系边；
- 最大关系距离；
- 是否包含配偶及姻亲；
- 是否包含收养、继养或谱系承继；
- 是否排除争议、草稿和已结束关系；
- 计算结果的缓存和失效方式。

首期策略应保持简单、可解释，并由后端统一计算。

## 10. 查询裁决

每个查询执行：

1. 宗族空间成员校验；
2. 角色能力校验；
3. 行级范围过滤；
4. 对象存在性保护；
5. 字段级隐私裁剪；
6. 附件和来源二次策略；
7. 返回允许动作和裁剪说明。

禁止：

- 先查询全量数据再由前端隐藏；
- 仅在 Controller 注解中完成全部数据范围控制；
- 通过多个接口拼接恢复被裁剪字段；
- 缓存未包含用户、宗族和策略版本的敏感响应。

## 11. 来源和附件

来源元数据、引文内容和附件文件分别授权。

例如，用户可能：

- 知道某来源存在；
- 查看来源书目信息；
- 查看公开引文；
- 但无权下载原始影像。

附件访问必须：

- 使用短期授权；
- 校验当前权限，不永久复用旧下载链接；
- 记录下载和预览审计；
- 不暴露真实存储路径；
- 支持病毒扫描和文件状态；
- 对封存材料采用更严格审批。

## 12. 导入和导出

### 导入

- 上传权限与正式生效权限分离；
- 导入只能形成草稿、候选主张或变更请求；
- 导入中的敏感字段按上传者权限和目标对象策略处理；
- 错误文件本身也可能包含敏感信息，下载需要授权。

### 导出

创建任务时冻结：

- 查询条件；
- 用户身份；
- 宗族空间；
- 授权范围；
- 隐私策略版本；
- 字段选择；
- 导出用途。

生成时再次确认权限未被撤销。

导出文件：

- 按字段裁剪；
- 设置到期时间；
- 使用短期下载凭据；
- 记录创建、生成、下载和删除；
- 高敏导出要求额外审核。

## 13. 审计

必须审计：

- 登录失败和账户锁定；
- 成员邀请、角色和范围变更；
- 敏感人物和封存材料访问；
- 附件下载；
- 来源和主张变更；
- 正式命令提交、审核、执行和补偿；
- 导入和导出；
- 隐私策略调整；
- 管理员跨宗族操作。

审计记录至少包含：

- 操作者；
- 宗族空间；
- 操作和资源类型；
- 业务资源标识；
- 结果；
- 权限决策摘要；
- 请求 ID；
- 时间；
- 必要的变更摘要。

审计中不保存密码、令牌、完整高敏字段或无必要的附件原文。

## 14. 缓存与失效

权限缓存键必须包含：

- 用户；
- 宗族空间；
- 角色和范围版本；
- 组织结构版本；
- 隐私策略版本；
- 必要的对象版本。

以下事件触发立即失效：

- 成员停用；
- 角色或范围变更；
- 谱系结构变化；
- 对象隐私等级变化；
- 在世状态变化；
- 封存或解封；
- 用户会话撤销。

首期不引入复杂分布式权限缓存；先保证正确性。

## 15. 错误与存在性保护

- 未认证返回 401；
- 已认证但无操作能力通常返回 403；
- 用户无权知道对象是否存在时返回 404；
- 字段被裁剪时响应可返回业务化 `redactions`，但不能泄漏被裁剪值；
- 审计页面可以展示拒绝原因，但受独立权限保护。

## 16. 安全测试门禁

至少覆盖：

- 跨宗族 ID 越权；
- 谱系 SELF 与 SUBTREE 边界；
- 结构移动后的权限变化；
- 提交人审核自己；
- 在世人物字段裁剪；
- 无权对象存在性保护；
- 附件短期链接失效；
- 导出权限撤销；
- 缓存失效；
- 管理员和普通成员接口差异；
- 批量接口中混入越权对象；
- 审计信息自身的访问控制。
